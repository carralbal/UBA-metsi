# N29 · Rúbrica y evidencias

## Escala

- `0`: lista de herramientas o pasos;
- `1`: automatización sin gobierno;
- `2`: cadena trazable con recuperación o cierre incompletos;
- `3`: liberación íntegra, autorizada, gradual y reparable.

## Rúbrica de liberación

| Criterio | Pregunta de evaluación | Evidencia de nivel 3 |
|---|---|---|
| Procedencia | ¿El cambio vuelve a una decisión? | Conecta issue, commit, revisión y riesgo. |
| Git | ¿La historia conserva unidades coherentes? | Commits trazables, revisables y atribuibles. |
| GitHub | ¿La colaboración incorpora evidencia y autoridad? | Pull request con controles y decisión explícita. |
| Artefacto | ¿Se promueve una unidad inmutable? | Registra firma, dependencias y configuración. |
| Puerta | ¿La aprobación responde al riesgo? | Puede detener aunque la cadena esté verde. |
| Exposición | ¿Despliegue y liberación están separados? | Define población, bandera, señal y reversión. |
| Recuperación | ¿Incluye código, datos y terceros? | Elige rollback, rollforward o compensación viable. |
| Cierre | ¿Operación sostiene el cambio? | Conserva soporte, riesgo, aprendizaje y retiro. |

## Evidencia de aprendizaje

El expediente debe explicar por qué una cadena automatizada exitosa no autoriza por sí sola y reparar un efecto que el código no puede revertir.

## Conexión acumulativa

Las señales de liberación alimentan en N30 objetivos de servicio, respuesta a incidentes y aprendizaje operativo.
